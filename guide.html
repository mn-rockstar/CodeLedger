The short version

Solve a problem. It's already committed.

CodeLedger watches LeetCode while you work. The moment a submission comes back Accepted, it commits your solution and the problem statement to a GitHub repository you own — no copying, no pasting, no git add.

It only ever acts on accepted submissions. A wrong answer, a timeout, a compile error: nothing happens, nothing is written. Your practice history builds itself, and the repo stays clean enough to show someone.

Under the hood

How it works

LeetCode never changes its address bar when you submit — the result appears in place. So rather than watching the URL, CodeLedger watches the page itself for the result banner LeetCode draws, then asks LeetCode's own API for the details it needs.

One time only

Setting it up

1

Pin it to your toolbar

Click the puzzle-piece icon at the top right of your browser, find CodeLedger, and click the pin beside it. Extensions can't pin themselves — that one is always the browser's call, not ours.

2

Connect GitHub

Click the CodeLedger icon, then Login with GitHub. You'll approve it on GitHub's own page — CodeLedger never sees your password.

3

Pick where solutions go

Either Create repo to make a fresh private one, or Link repo to use one you already have. For linking, paste the repo's GitHub link — or just type its name, and your own account is assumed.

That's it. Go solve something; the first time, it will ask you to confirm which LeetCode account is yours.

Status chip

Reads Connected when GitHub and a repo are both set. If it says Setup, something still needs picking.

Solved, and the split

The big number counts every problem committed at least once — re-solving one never counts it twice. Below it, the same total split by difficulty. Those colours run light to dark on purpose: difficulty is a scale, not three unrelated labels.

3

Four measures

Consecutive days solving, solves in the last week, the language you use most, and your most recent problem. A streak survives until you miss a whole day — it won't reset just because you haven't solved yet today.

4

Who and where

The GitHub account committing, the LeetCode account being watched, and the repo receiving files. The repo name is a link — click it to open the repo.

5

Reset stats

Sets the counter back to zero and clears stats.json in your repo. It asks before doing it. Your committed solutions are never touched.

6

Disconnect

Forgets your GitHub connection, the repo link and your stats on this device. Nothing on GitHub is deleted — everything already committed stays exactly where it is.

Before you're connected

Until setup is done the popup shows different controls: Login with GitHub starts the sign-in; Create repo makes a new private repository from the name you type; Link repo points at an existing one. Disconnect GitHub backs all the way out.

You may also see Use detected account. That appears when the LeetCode account signed in right now isn't the one you confirmed — clicking it makes the current account the confirmed one.

The output

What lands in your repo

One folder per problem, numbered so it sorts the way LeetCode does. The file extension follows whichever language you solved in.

your-name/solutions ├── 0001-two-sum/ │ ├── README.md the problem statement │ └── two-sum.py your accepted code ├── 0013-roman-to-integer/ │ ├── README.md │ └── roman-to-integer.py └── stats.json your counts, so they survive a reinstall

The commit message carries the run's numbers, which turns your git history into a performance log:

Time: 7 ms (58.0%), Memory: 19.2 MB (41.9%)

Solve the same problem again and the files are updated in place rather than duplicated — you get a second commit on the same folder, so improvements show up as history.

On the page

What the messages mean

A small box appears at the bottom-right of LeetCode while CodeLedger works. It clears itself after a few seconds, so it's easy to miss — that isn't a failure.

CodeLedger: committing…

Working. It has your code and is writing to GitHub.

CodeLedger: committed ✓

Done — the files are in your repo.

CodeLedger: not connected — open the popup to connect GitHub

Something in setup is missing: the GitHub connection, the repo link, or both. Open the popup and it'll show you which.

Switching tabs mid-commit is fine. The work continues in the background; you just won't see the checkmark.

A deliberate interruption

The account check

The first time it commits — and any time the LeetCode account signed in differs from the one you confirmed — CodeLedger stops and asks before writing anything:

Confirm your LeetCode account before committing: your-handle — is this you?

Yes, this is me Skip this commit

This exists because a shared machine, or a second LeetCode account, would otherwise quietly push someone else's work into your repo. Ignoring the prompt counts as skipping — nothing is committed unless you say so.

When it misbehaves

Troubleshooting

Symptom Most likely cause
Nothing happens after Accepted The LeetCode tab was open before the extension was updated. Refresh the tab.
A commit appeared, but no CodeLedger message Another LeetCode-to-GitHub extension is also installed and got there first. Disable it.
"Not connected", but the popup looks fine The repo link is missing even though GitHub is connected. Re-link it in the popup.
Counts look wrong or empty Stats begin from the first solve after installing. They aren't backfilled from problems solved earlier.

Clearing browsing data wipes the setup. Browsers treat extension storage as site data, so a cleanup can remove your repo link — and sometimes the GitHub connection with it. Reconnect from the popup; your repo and everything in it are untouched.

What's kept

Privacy

No analytics, no tracking, no accounts. Your GitHub token is stored on your own device and is sent nowhere except GitHub itself. Your solution code goes only to the repository you picked.

CodeLedger reads your submission from LeetCode using the same web API the site itself uses, from the tab you're already signed into. The only other service involved is a small script that completes GitHub sign-in — it handles one step of the handshake and stores nothing.

Creating a repo through CodeLedger makes it private by default. If you link an existing public repo, your solutions will be public — that's your call to make, so check which one you're pointing at.

CodeLedger is a browser extension for LeetCode. It commits only accepted submissions, only to the repository you choose, and only from the account you confirm.
